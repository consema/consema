# HCL 0.11.0 performance baseline

## Environment

- Date: 2026-08-07 (local)
- Windows 11 Pro 10.0.26200, x86-64
- Rust 1.97.1 stable (`8bab26f4f 2026-07-14`), LLVM 22.1.6, `--release` profile,
  `cargo run --locked --offline --release -p consema-conformance --example hcl_baseline -- <iterations>`
- Commit: 0.11.0 development workspace (unreleased, HEAD `a447ce6`)
- CPU: 13th Gen Intel Core i9-13900HX, 32 logical processors; no CPU affinity,
  isolation, or background-process suppression

## Corpus and operations

Both inputs are repository-authored production-shaped fixtures under
`conformance/fixtures/hcl/`, pinned byte-for-byte by the fixture gate
(`consema-rs/consema-conformance/tests/hcl_fixtures.rs`；拆分前布局为 `crates/consema-conformance/tests/hcl_fixtures.rs`):

- `tf/main.tf` (1,139 bytes), SHA-256
  `1c9a57fc4f6b7358d22aac8c2f13c7b9ab421194007eac7d6673e7b5558e2436`:
  Terraform-like terraform/provider/variable/locals blocks, nested
  `required_providers` blocks, object literals and attribute expressions.
- `tfvars/terraform.tfvars` (481 bytes), SHA-256
  `b085a2b416ebf8a24d0794cc5407158290f3fae8166d2e442b0306b813628b61`:
  top-level attributes only, including object/tuple literals and an
  indented heredoc string.

Operations measured per iteration:

1. **parse** — `hcl.native@1` (main.tf) and `hcl.tfvars@1`
   (terraform.tfvars) formation under default limits with byte-exact render
   closure;
2. **projection** — exact `hcl.projection.body@1` record projection (the
   tfvars fixture is fully literal-complete, so the default exact target
   applies);
3. **materialization** — canonical `hcl.canonical-document@1` including the
   mandatory reparse closure verification, returning no Document on any
   mismatch.

Recovery and adversarial-size behavior (expression depth, template/heredoc
size, number digits, body nesting, item counts) are covered by the hardening
suite (`consema-rs/consema-conformance/tests/hcl_hardening.rs`；拆分前布局为 `crates/consema-conformance/tests/hcl_hardening.rs`), not by this
wall-clock baseline.

## Results (5,000 iterations, 3 samples)

| Operation | Sample 1 ns/op | Sample 2 ns/op | Sample 3 ns/op | Median ns/op |
|---|---:|---:|---:|---:|
| parse hcl.native (main.tf, 1,139 B) | 38,747.6 | 55,222.4 | 55,465.0 | 55,222.4 |
| parse hcl.tfvars (terraform.tfvars, 481 B) | 24,164.8 | 23,980.6 | 24,748.4 | 24,164.8 |
| projection hcl.body | 44,774.0 | 34,867.0 | 32,552.2 | 34,867.0 |
| materialization hcl.canonical-document | 64,190.4 | 64,799.4 | 57,318.8 | 64,190.4 |

The tfvars parse measures the same grammar under the top-level
attributes-only structural rule; its corpus is denser (nested literals and
heredoc), so per-byte cost is comparable to the native fixture's.
Materialization dominates projection because the contract reparses the exact
generated bytes and compares the native body/expression semantics (numbers by
canonical-decimal value equality, everything else by structural equality)
before publishing; the cost is the price of the closure guarantee. The parser
is debug-safety instrumented and deliberately favors bounded allocations over
speed; the baseline is a reproducibility gate, not an optimization claim.

The complete sample spread is retained deliberately. Future comparisons must
use the same corpus, operation definitions, release profile, and iteration
count. Results from another machine or toolchain must be reported separately
instead of being merged into this baseline.

## Reproducibility

```text
cargo run --locked --offline --release -p consema-conformance --example hcl_baseline -- 5000
```

The harness ends with the closure contract assertions: both pinned fixtures
render byte-exactly and the tfvars record materializes with
`MaterializationFidelity::Exact`, so the baseline never runs on a corpus whose
closure contract is broken.
