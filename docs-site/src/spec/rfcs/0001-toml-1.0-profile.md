# RFC 0001: `toml.1.0@1` 原生语义、投影、查询与编辑契约

- 状态：Implemented in Consema 0.2.0
- 目标版本：Consema 0.2.0
- 规范来源：TOML 1.0.0
- 语言实现：Rust 首先；该文档是语言无关契约

## 1. 决策摘要

Consema 0.2.0 增加格式家族 `toml@1` 和冻结 Profile `toml.1.0@1`。它只接受完整、合法的 TOML 1.0 UTF-8 文档；语法错误在 0.2.0 中是 `FatalFormationFailure`，不得伪造为成功文档。容错恢复是后续独立 capability，未声明即不支持。

TOML 不复用 JSON object/member 模型。公共文档身份增加 `TomlItem`、`TomlEntry`、`TomlKey`、`TomlArrayElement` 四种角色；table、inline table、array 与 array-of-tables 是不同的原生 item 类别。公共值投影发生在显式 projection 阶段，不能反向抹掉原生差异。

Rust 实现可使用 `toml_edit 0.22.x` 作为解析后端，但后端不是规范。替换后端不得改变本文的 profile、身份、顺序、投影、查询、诊断或编辑结果。

## 2. 文档与身份模型

每次成功 parse 产生新的不可变 snapshot。默认 render 必须逐字节等于输入；token/trivia 索引必须无空洞、无重叠地覆盖全部输入。所有 `NodeRef`、`Span`、query match、provenance 与 edit target 都绑定该 snapshot。

原生实体如下：

| 实体 | `NodeRole` | 含义 |
|---|---|---|
| `TomlItem` | `TomlItem` | scalar、array、inline table、table 或 array-of-tables |
| `TomlEntry` | `TomlEntry` | 一个 table/inline-table 中有序的 key-to-item 关联 |
| `TomlKey` | `TomlKey` | entry 的已解码直接 key segment 及其源身份 |
| `TomlArrayElement` | `TomlArrayElement` | array 或 array-of-tables 中有序的元素关联 |

根永远是 `RootTable` item。原生 item 的闭集为：

- `String`、`Integer`、`Float`、`Boolean`；
- `OffsetDateTime`、`LocalDateTime`、`LocalDate`、`LocalTime`；
- `Array`、`InlineTable`、`RootTable`、`StandardTable`、`ImplicitTable`、`DottedTable`、`ArrayOfTables`。

这里的 `TomlItem` 是 Consema 原生语义超类型，不声称 TOML 规范把 table 称为 value。`Integer` 是有符号 64 位语义；`Float` 保留解析得到的 IEEE-754 binary64 位模式；日期时间保留 TOML 的字段与 offset。原始词法表示始终由 source/span 保存。

### 2.1 dotted key

`a.b.c = 1` 同时具有：

1. 原始语法中的三个 key segment/span；
2. 逻辑树中逐层的 table entry；
3. 叶 item `1` 的独立身份。

实现不得把整条 dotted key 压成一个普通字符串，也不得把隐式 table 与显式 `[table]` 当成同一原生类别。直接 `TomlEntry::name()` 只返回所在 table 的一个解码 segment；完整逻辑路径通过逐层 entry 导航获得。

### 2.2 顺序与 span

table entry、array element 和 array-of-tables element 的顺序是确定的结构顺序。每个显式 key、scalar、array、inline table、table header/body 都应有精确 span。没有独立连续语法区间的隐式逻辑节点允许使用其创建 key segment 的 span；不得伪造覆盖无关字节的“大概范围”。

## 3. 解析、资源限制与诊断

形成文档前必须依次执行：

1. `max_source_bytes`；
2. UTF-8 验证；
3. TOML 1.0 语法/语义验证；
4. `max_token_count`、`max_node_count`、`max_nesting_depth`。

任何资源限制命中都返回明确的 `core.parse.resource-limit@1`；TOML 语法失败返回 `toml.parse.syntax@1`，携带后端可证明的最小 span 和稳定参数。不得返回截断的成功文档。

0.2.0 声明的 formation capability 是 `toml.document.complete@1`，不声明 recovery capability。

## 4. 原生查询域

冻结查询域 `toml.native-semantic-query@1`，输入和根输出角色均为 `TomlItem`。标准 operator registry：

| operator | 输入 | 输出 | 参数 | 语义 |
|---|---|---|---|---|
| `toml.try-table-entries@1` | `TomlItem` | `TomlEntry` | 无 | table/inline table 的直接 entries；其他 item 为空 |
| `toml.entry-name-equals@1` | `TomlEntry` | `TomlEntry` | `name:String` | 精确比较已解码直接 key segment |
| `toml.entry-item@1` | `TomlEntry` | `TomlItem` | 无 | 取得关联 item |
| `toml.try-array-elements@1` | `TomlItem` | `TomlArrayElement` | 无 | array/AOT 的直接 elements；其他 item 为空 |
| `toml.array-element-item@1` | `TomlArrayElement` | `TomlItem` | 无 | 取得元素 item |

通用 `core.take@1`、`core.distinct-by-identity@1`、selection、concat、structure-order-merge、limit 与 cancellation 语义不变。验证必须在执行前完成；角色组合错误、未知版本和错误参数不得延迟到游标消费阶段。

## 5. 到 PortableValue 的投影

冻结目标 `toml.best-exact-core@1`。映射如下：

| TOML 原生类别 | PortableValue |
|---|---|
| Boolean | Boolean |
| Integer | Integer |
| Float | BinaryFloat64 |
| String | String |
| LocalDate | Date |
| LocalTime | Time |
| LocalDateTime | LocalDateTime |
| OffsetDateTime | OffsetDateTime |
| Array | Sequence |
| Root/Standard/Implicit/Dotted/Inline Table | Object |
| ArrayOfTables | Sequence&lt;Object&gt; |

TOML 合法文档不含重复逻辑 key，因此 table 可无损进入 unique-key Object。table flavor、引号、数字基数、underscore、注释和排版属于原生/文档事实，不属于 PortableValue；投影对值语义可为 `Exact`，但 provenance 必须把每个产生的 value 和 object association 映射回源 `NodeRef`/span。

如果 TOML 日期时间字段超出 PortableValue v1 的闭集（例如实现接受但 core 禁止的 leap second），投影必须整体失败并报告 `toml.projection.unrepresentable-datetime@1`，不能截断、归一化或静默替换。

0.2.0 的 Rust API 可使用 TOML 专属 request/report 类型；0.3.0 将抽取语言无关 wire contract。API 形状不是绕过显式 target、limits、report 与 provenance 的许可。

## 6. 标量编辑

编辑事务绑定一个 base snapshot，只接受 `TomlItem` 角色的 scalar target。container、entry、key 和 array-element 不能冒充 scalar。

支持两种操作：

- exact literal：候选字节必须独立解析为一个完整合法 TOML 1.0 scalar；
- semantic scalar：只接受可表示为 TOML scalar 的 PortableValue，并要求显式 representation policy。

策略为：

- `ExactLiteral`：只能走 exact literal 操作；
- `PreserveCompatible`：新值必须保持原生 scalar 类别；
- `CanonicalForProfile`：使用冻结的 TOML 1.0 canonical 表示；
- `PreserveElseCanonical`：兼容时保类，否则产生诊断并 canonical 化。

事务必须先验证全部 target、冲突和候选表示，再一次性替换并重新 parse。任一失败时旧 snapshot 是唯一结果；成功时产生新 snapshot、完整 `ChangeSet` 和可解释的 node mapping。

0.2.0 不包含 key rename、table move、insert/delete 或 container replacement；这些操作不能用字符串拼接伪装成 scalar edit。

## 7. Conformance 与验收

0.2.0 至少覆盖：

- TOML 1.0 scalar 全类别与特殊 float；
- quoted/bare/dotted key、standard/implicit/dotted/inline table；
- array 与 array-of-tables；
- exact render 与 exhaustive source coverage；
- snapshot/role 隔离；
- query 类型验证、顺序、selection、limit、cancellation；
- projection 的完整值、provenance 和不可表示日期时间失败；
- scalar edit 成功、原子失败、重叠冲突与重 parse；
- UTF-8、语法错误和四类 parse limits。

语言无关向量必须包含输入、profile、预期结构/诊断/投影事实，Rust 测试是第一个 runner 而不是规范本身。

## 8. 非目标

- TOML 1.1、非标准扩展、自动 profile 猜测；
- `.env`、环境变量展开、include、merge、schema validation；
- 语法恢复与半合法文档编辑；
- 将 TOML table 等同为 JSON object；
- 依赖 `toml_edit` 私有类型或错误文案作为公共协议。
